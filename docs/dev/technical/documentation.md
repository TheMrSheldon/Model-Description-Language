\page dev_documentation The documentation
\tableofcontents

This documentation is generated by Doxygen with the doxygen-awesome theme. Its configuration is part of the CMake
build (`cmake/Docs.cmake`) rather than a Doxyfile, and it is built with

<div class="lang-bash">

```bash
cmake --workflow --preset docs      # or: cmake --preset conf-docs && cmake --build --preset docs
```
</div>

into `build/docs/documentation/html`. Building it needs Doxygen, Graphviz, Perl and BibTeX.

# Structure
| Directory | Content |
|---|---|
| `docs/user/` | the user guide: installation, usage, examples |
| `docs/foundations/` | the deep learning background, written as a learning resource |
| `docs/dev/spec/` | the specifications |
| `docs/dev/technical/` | how the compiler works and why |
| `docs/references/` | the bibliography (`*.bib`) |
| `docs/doxygen/` | the page header, layout, stylesheet and scripts of the site |
| `include/` | the C++ API (doc comments in the headers) |
| `std/` | the standard library (doc comments in the `.dlm` files, see below) |

Every page starts with `\page id Title` (or a first heading `# Title {#id}`) and is linked into the tree with
`\subpage id` from its parent's index page. Index pages show their subpages as cards: a list in `<div class="cards">`, each item a
`\subpage` followed by a one-line description on the next line (styled by `docs/doxygen/mdl.css`).

# Citations
`\cite key` cites an entry of the bibliography. The bibliography is split by topic into several files in
`docs/references/` (e.g. `basics.bib`, `models.bib`, `compilers.bib`); all of them are passed to Doxygen, so a new
file only needs to be created there. The keys share one namespace: the docs build fails if a key is defined twice
(`cmake/CheckBibKeys.cmake`). Citations work in the hand-written pages, in C++ doc comments, and in the doc comments
of the standard library.

# The API of the standard library
Doxygen has no parser for MDL. The usual workaround would be an input filter that rewrites MDL as C++ declarations,
but then modules would be shown as C++ classes and hyperparameters as template parameters. Instead, `mdl-doc`
(`src/commands/mdl-doc.cpp`) generates Doxygen *pages*:

1. It analyzes each file of the package with the frontend (`mdl::parser::analyze`), i.e., with the same parser,
   import resolution and visibility rules as the compiler, and takes the definitions from the semantic index.
2. It writes one page per file (e.g. `std.nn`) with the file's `@file` comment, and for its `public` modules,
   structs and functions an overview table (name and brief description) followed by one card per definition, like
   Doxygen's own member documentation. A module's card lists its public members in a table; its public methods get
   cards of their own. Re-exports are listed at the end. Every card ends with "Definition at line N of FILE", linking
   to the line on the file's source page (`<file>_source`: the numbered, highlighted source, generated as well). On the
   source pages, names link to their documentation (the card), or to their definition in the source if they have no
   card; local variables and parameters are not linked. The targets come from the semantic index.
3. Declarations are shown as MDL code; doc comments are passed to Doxygen as written, so `@param`, `@return`,
   `\cite`, math and `\ref` work as everywhere else. (Only `@brief` is dropped and its text kept as the first
   paragraph: on a page, Doxygen would move it to the top of the page.)

The generated pages have the IDs `<file>` and `<file>_<name>` (and `<file>_<module>_<method>` for methods), with
dots replaced by underscores; overloads get a counter (`std_activations_softmax_2`). Hence, `\ref std_nn` links to
the page of `std.nn`, and `\ref std_nn_Linear` to `Linear`.

Doxygen highlights only a few languages itself (C++, Python, ...), and only sparsely (keywords, strings, comments), and
drops the language of other fenced code blocks. Hence, code blocks are marked by a surrounding `<div>`: `<div class="mdl">` for MDL (colored by
`docs/doxygen/mdl-highlight.js`), and `<div class="lang-NAME">` for any language of highlight.js, e.g. `lang-cmake`,
`lang-bash`, `lang-yaml`, `lang-json` (colored by `docs/doxygen/lang-highlight.js`, with highlight.js from cdnjs). Both
use doxygen-awesome's code colors, so they follow the light and dark theme. C++ is marked as well (`lang-cpp`), for the same look. For example:

~~~
<div class="mdl">

```
module FFN[indim: uint, outdim: uint] { ... }
```
</div>
~~~

# Versions
The workflow `.github/workflows/docs.yml` builds the documentation for every pull request (with warnings as
errors), publishes the state of `main` as `nightly/`, and every release as `vX.Y.Z/` (and as `latest/`) on GitHub
Pages. Doxygen has no version selector, so versions are distinguished by the URL; the root redirects to `latest/`, and
`versions.json` lists the published versions.
